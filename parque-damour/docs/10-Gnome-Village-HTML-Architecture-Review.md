## 1. Overview and physical layout

Gnome Village is a phone-first, single-canvas, deterministic village simulation: a 72×72-tile island in a sea, with hydraulic erosion, a population of up to 44 gnomes who build from carried logs/stone/reeds, animals, weather and seasons, drawn as a rotatable 2:1 isometric scene on one `<canvas>` with "glass" HTML overlays for the HUD. The whole game is one strict-mode IIFE (316–12243) of ~11,900 lines of JavaScript; the only thing it leaks is a ~344-key debug/harness object `window.__GV` (12223–12241). There is no module system, no build step, no assets (fonts come from Google Fonts, lines 10–12; sound is procedural Web Audio), and no persistence beyond a seed in the URL hash. The player has two modes: **creator** (god-hand terrain tools and watching) and **gnome** (one avatar driven by taps, with a build panel); both share the same sim and renderer.

## 2. Architecture

### 2.1 Main loop
- `boot()` (12127) initialises render/tools/input, calls `newIsland(seedFromHash())`, wires every control (12131–12220) and starts `requestAnimationFrame(frame)` (12221).
- `frame(ts)` (12070–12096): re-arms rAF first; real `dtr = min(0.05, Δ)` (12073); `simAcc += dtr * T.speed`; `nsMax = clamp(ceil(speed*2.2)+4, 8, 48)` with a wall-clock budget of 26/13/9 ms for speed >6 / >3 / else (12082); `lite = speed>6 ? 3 : 1` (12083); runs `simulate(SIM_DT=1/60, lite)` while `simAcc >= SIM_DT` (12084); `rebuildSurface()` once per frame if any step ran (12085); drops backlog rather than chasing it (12086); `updateAudio(dtr)` in real seconds (12088); `turnStep`, `keepCentre`, `followStep`, `ambientFx` (12089–12091); `draw()`; `updateHUD(dtr)` (12094); `ftNote` (12057) for the perf overlay and auto quality step-down.
- `simulate(dt, lite)` (12024–12040) phase order: `updateTime`, `updateWeather` → water (`waterStep` in ≤0.034 s substeps; with `lite&2` batched every ≥0.030 s, 12028) → `slumpStep` → `rebuildSurface` unless `lite&1` (12030; never fires from the UI since `lite` is 1 or 3 — see §16) → `updateMaterials`, `refreshIndex`, `updateGnomes`, `updateFlora`, `updateCritters`, `updateSnowmen`, `floodWatch`, `prepFade`, `flyerStep`, `boatStep`, `updateParts` → every 1.2 s the planner tick `tallyShortfall; planEmergent; planVillage; households` (12038) → `breeding` (12039). Each phase is lapped into `SP` (12014).
- Determinism: fixed step + seeded sim PRNG (`mulberry32` 583; `rng`/`rnd`/`rint`/`pick`/`chance` 589–593, draw counter `rngN` 588) vs a separate visual PRNG `vrng`/`vrnd`/`vrint`/`vpick`/`vchance` (594–598) for particles, sky, sound and birds; reseeded from `world.seed` at 887. Same seed + same steps = same isle regardless of frame rate (comment 12015–12022).

### 2.2 World data model
- Grid: `S=2` fine tiles per legacy "v7" tile, `N=36*S=72`, `NC=5184`, `NV=73` vertices per side (567–568); `S2=4` (576). Legacy `*S`/`*S2` scaling is applied by hand at ~340/70 sites (reader 02).
- Heights in "levels": `EMAX=9`, `SEA=2.0`, sea surface `SEAS=2.5`, `DIG_FLOOR=1.0` (570–572). Screen: `TW=26`, `TH=13`, `EH=26` px per level at zoom 1 (569).
- Per-tile typed arrays (612–673): ground `E`, as-painted `E0`, water depth `WD`, `SOIL`, `FLOW`, flow direction `FDX/FDY`, footfall `WEAR` (619), material `MAT` (621; enum `MEA/GRS/SCR/ROK/SNW/SND/WAT` at 671), construction plot `PREP/PREPF` (622–623), trodden `TROD` 624, path look `PATHST` 625, deck height `BRIDGE` 626, flags `PIER/STEPS/DAM/PAVE/OCC` 627–631, activity counters `FISHN/CLIMBN/QUARRYN` 632–634, creator-hand bits `MADE` 635, sea mask `SEAC` 636, `RIVER` 655, `ICE` 656, edge discharges `FX/FY/FP/FQ` 663–666, sediment `SED/SAND/KSOFT` 667–669, inflow/discharge vectors 670–673; mine pit `MINEB/MINEZ` 2996–2997; flood channel `CHAN` 1985.
- The sea is a BFS flood from the map edge over `E<=SEA` (`markSea` 642); off-map ground is `SEA-0.8` (674).
- Drawn surface: vertex heights `V` and water `VW` (699–715) built by `rebuildSurface` (713) with edge-preserving `smoothSurface` (780, strength 0.5, edge 0.42); `eLerp` (790) bilinear ground, `topAt` (795) deck/ice/water/ground a foot rests on, `slopeOf` (804). Sim and pathing read the true `E`; drawing and foot placement read `V` (comment 771–779).
- Clock `T={abs,f,day,season,light,speed,cold,thaw,ds}` (814); weather `W` (845) with table `WK` (829–838).
- Registries: `world` (883: seed, name, springs, camp, rivers), `flowers`/`cover` (884), `trees/bushes/rocks/builds/parts/stumps/critters/birds` (1690), `gnomes`/`marks` (1371), `gorges` (1525), `floods` (1985), `store` (2409), `village` (2468, an untyped grab-bag of ~40 fields), `villages` (2485, max 2), `boats` (11710), `village.flyer` (11352+), `snowmen` (4729), `STATS` (4658).

### 2.3 Entity model
- Gnome: `makeGnome` (1387–1399) produces one flat record (id, name, sex, x/y, age in days, stage, hunger/energy/warm, `st` state string, `job` object, path cache, carry, home/mate/parents/project, craft tally `did`…); avatar is the same record with `g.player=true` (5635). Ages: child 2 d, adult 24, elder 48, leaves at 84 (`AGE_*` 1375). Crafts emerge from `tally`/`craftOf` (1381–1386; ≥6 tallies and ≥40 % share).
- Animals: plain objects `{k:'rabbit'|'deer'|'fox', st, t, tx, ty, face, scare, …}` created by `seedCritters` (1753) and stepped per kind in `updateCritters` (2299); decorative `birds` capped at 6 (`landBird` ~2286, visual RNG).
- Buildings: `mkBuild` (2768, footprint `x0,y0,fw,fh,rot`, door `dx,dy`) or `mkProj` (2843, tile/point projects with `tiles[]`, `ends[]`, `decks[]`); data tables `BT` (2411, 33 types with `w,s,f,work,label,fw,fh,beds,roof`), `HOUSE` (7036, 9 house types with wall materials, windows, door, roof, extras), `STAGED` (3836, 27 piece-built types), `SPAN` (2457). Construction state lives on the build: `plan[]`, `pi`, `got{}`, `stc{}`, `need{}`, `yx/yy` (`stageProject` 4107).
- Machines: `village.flyer` object (balloon or glider, 11352–11560) and `boats[]` (`launchBoat` 11737; `{id,home,k,moor,x,y,h,st,crew,path,…}`).
- Particles: `P(o)` (2386) with a hard cap of 220; kinds dust/smoke/chip/mist/logf/spark/bee/drop/splash/ring/fly/heart/zzz/note (`updateParts` 2396, `drawPart` 8609).

### 2.4 Render pipeline order
`draw()` (12042–12053): `computeAmbient` (6452) → `setTransform(dpr)` + `imageSmoothingEnabled=false` (12044) → `drawSky` (6525; offscreen backdrop repainted every 260 ms) → `drawIsland` (9578) → `drawGhost` (6037) only when `MODE==='gnome' && PB.pick` (12049) → `drawFocusMark` (10764) → `drawWeather` (10062, 12051).

Inside `drawIsland` (9578–9977): `rebuildSurface; projectVerts; tileOrder` (9580–9582) → colour epoch bump every 220 ms / 110 ms while turning (9586–9587: `yardRefresh; vertGrads; valleyShade`, `SHEEN/NIGHTC/WHITE_LIT`) → `buildSea; buildWV` (9589) → bucket every entity into the cell it paints after (`putWalker` ~9604, `frontKey` ~9634, `putProp` ~9660, buildings 9681–9696, gnomes 9697, boats 9699, parts/stumps/marks/springs/critters/birds/snowmen 9701–9709, flowers only `Z>0.8`, cover `Z>=1.0` 9710) → `frontFix` (8871, 9716) → fence pieces (9718–9723) → path pieces (`buildPieces` 8654 once per epoch when `Z>0.35`, 9725–9727) → walk cells back to front: `paintCell` (~9736–9935: ground gradient/sub-quads, puddles, steps/mine tiles, sea sheet, fillet, inland water, water detail) then props via `drawProp` (9540, kinds 0–20) → deferred props, airborne flyer, flying birds (9973–9976).

### 2.5 Where sim and drawing are separated
- Sim truth is `E`/`WD`/typed arrays; the renderer derives `V`, `VW`, `AO`, `VGX/VGY`, colour caches, path pieces per epoch and never writes sim fields (comments 771–779, 8172, 8274, 8816–8818). Exceptions flagged: `drawWheel` spawns splash particles (10538), `drawSpring` spawns splashes (8602), `fencePieces` caches on `b._fpc` (7510) — all on the visual stream, so determinism holds.
- Visual randomness (`vrnd` …) is a separate stream from sim randomness (585–598); audio reads sim state but writes none (§8).
- Fast-forward: above 6× the `lite` bits halve the water solve and (by design) skip the per-step surface rebuild (12028–12030, 12083); sound cues are rate-limited by real time scaled by speed (`aOK` 6131).

## 3. The MODE system: creator vs gnome

### 3.1 Variables and the switch
- `let PLAYER=null, MODE='creator';` (5630). `PLAYER` is the avatar's gnome record (set by `playerArrive` 5632); `MODE` is `'creator'` or `'gnome'`. `PLAYER_HOLD` (5631) is the set of avatar states in which a tap is refused as "busy".
- `setMode(m)` (11252–11270) is the only switch, toggled by `#bPlay` (287; wiring 12184). Entering gnome: spawn the avatar if none or dead (`playerArrive`, 11255), `MODE='gnome'; setTool('hand')` (11256), select + follow the avatar, zoom to ≥1.5 if below 1.3, show the card, 6-second tutorial toast (11257–11258). Entering creator: `MODE='creator'` (11261), drop follow and selection, `pbClear(); closeBuild(); updateGbar()` (11263), toast "`<name>` goes on as one of the village/hamlet" (11264). Both: `body.classList.toggle('gnome')` (11266), `#bPlay` text "Creator" ↔ "Be a gnome" + `aria-pressed` (11267), `updateGrow(); layoutOverlays()` (11268).
- `newIsland` (12101) forces creator mode: `PLAYER=null`, `MODE='creator'`, removes `body.gnome`, resets the button, clears `PB` (12107–12108).
- Every `MODE` read site (verified): 5696 brain swap; 8435 selection ring; 9550 player ring; 10830 card "doing"; 11020 card re-show from the ghost bar; 11223 tap routing; 11256/11261 set; 11266–11267 class/button; 11408 `watchJoin`, 11417 `flyOK`, 11426 `startFlight`, 11515 `gliderStep` (avatar never joins a flight crowd/crew while in gnome mode); 12049 ghost draw; 12107 reset; 12184 button.

### 3.2 What changes in rail / HUD / body classes
- CSS `body.gnome`: hides `#tools`, `#sizerow`, `#bUndo` (169); shows the `#grow` row (181); re-lays `#card` as a compact one-line strip with three side-by-side bars at 8.5 px (173–178, `.rel` full width 62).
- `#grow` (266–270): `#bBuild` 267, `#gstat` status chip 268, `#bPause` 269, `#bStop` 270 — driven by `updateGrow` (10995: early-returns unless gnome mode; shows chip/Pause/Stop only while the avatar owns an unfinished project; Pause reads "Go on" when `PB.paused`).
- Shared in both modes: HUD chips, speed group, rotate/Fit/Sound/Photo/New, census, events, card, toast, feed. `#gbar`/`#bld` are not CSS-gated by mode; the script only uses them with a `PB.pick` in gnome mode (11020, 12049). Photo mode (`body.photo` 164) and sheet state (`body.sheet` 226) are orthogonal to creator/gnome.
- Card text in gnome mode: the avatar reads "waiting for your tap" / "walking where you tapped" instead of `DOING` prose (10830); `#cName` gets " · you" (10824).

### 3.3 How the player gnome is controlled
- Spawn: `playerArrive` (5632–5641) on the sea shore nearest the green (within 80 tiles), adult `24+rnd(0.5,3)` days, hunger 0.25, energy 0.9, `player`+`stranger` flags, log + toast, walks toward the green.
- Input: a short tap (`moved<9 px`, `<420 ms`, hand tool) at 11223 routes to `playerCommand` in gnome mode, `tapSelect` in creator mode. `playerCommand` (11270–11279): if a build pick is active → `pbTap` + `updateGbar` (ghost follows the tap; walking is blocked); if the build panel is open → close it; else `playerTap(tx,ty)` and toast its return string with "`<name>: `" ('busy'/'asleep' special-cased, 'walking' silent); then re-follow and re-select the avatar.
- Tap cascade `playerTap` (5653–5688): refuse if `PLAYER_HOLD[g.st]` or inside ('busy'/'asleep'); wake and clear previous intent (`clearMarks`, `releaseBed`, job/partner/hat); nearest tree/rock/bush within a 0.75-tile box (sapling <0.35 age → pat; tree → chop; rock → quarry; bush with berries → pick, 5664–5666); building under the tile: unfinished site → `siteJob` (own site un-pauses; "lending a hand" at village sites, 5673), done fire → bed at bedtime else warm (5674), rack → eat if food (5675), home → `toBed` (5676), trap with stock ≥2 → collect (5677); water (`wetD>0.3` or `isWater && >0.2`) → fish from a free shore within 2.5 tiles (5680–5684); second tap on grass/meadow while standing within 0.8 → cut reeds (5686); else walk (`goTo`, 'walking', 5687).
- Autonomy: `playerDecide` (5642–5651) replaces `decide` only at 5696 (`g.player && MODE==='gnome'`). It skips while `BUSY`, hauls a carried load home, eats at hunger >0.86 if the store has food, sleeps on the spot at energy <0.06, seeks a fire/roof at warm <0.12, and when idle (and not `PB.paused`) continues the avatar's own project via `siteJob` (5650). `act` (4968), `needs` (5552), `moveGnome` (1600), `spaceOut` (5599) and the A* (1466) are shared unchanged with NPCs.
- Pathing: identical to NPCs — `goTo` (1569) with route reuse and `findPath` (1466); `openNear` (~1559) snaps a tapped occupied tile to a free neighbour.
- Exclusions by `g.player` flag (apply in both modes unless noted): never courts/pairs (4330, 4375, 4490, 4499), never conscripted to a flood fight (`canFight` ~2054), never leaves at age 84 (~5562 caller of `setOff`), never moved to the hamlet (4313), never miner/engineer/boatwright (3135, 3162, 3166), never rides the deer on a fetch (4211), never does animal jobs (~4909 in `decide`), never flees from hunger (~4835), never rows or rides a boat (11796, 11805, 11809), never a flight watcher/crew while in gnome mode (11408, 11417, 11426, 11515), tent never retired (3705). The avatar **can** be elected chief (`pickChief` 3260–3263 does not test `g.player`) and can be jostled, swept and dunked like anyone (4640, 4661, 4670).

### 3.4 Building as a gnome (v9.9)
- State `PB={pick,ghost,tiles[],paused}` (5817); catalogue `PB_LIST` (5818–5828, 26 `[type,label,hint]` entries: Tent, Cabin, Campfire, Woodpile, Drying rack, Lantern, Kitchen garden, Picket fence, Door path, Flagstones, Stone hearth, Steps, Fish trap, Log/Plank/Rope/Stone bridge, Dam, Waterwheel, Windmill, Beehive, Well, Rabbit fold, Kennel, Stable, Cart); per-tile-cost types `PB_SPAN` (5829); `PB_NEED_HOME` (10994: fence, steppath, garden need a finished home).
- Flow: `#bBuild` (267) → `openBuild` (11003: one project at a time; grid of buttons with `pbCostText` 5831; disabled "needs a home of your own") → `pbPick` (5998) → `pbGhost(type, tx, ty)` (5840–5989) returns `{ok, tiles, msg, mk}` with per-type placement rules and ranked failure reasons (wet → sea → taken → rock → steep → fallback, 5972–5975) → each tap `pbTap` (5991; pave runs up to 14 tiles) → `drawGhost` (6037) paints green/red tile panes → ghost bar `#gbar` (255; `updateGbar` 11018: name, cost, message, Place enabled iff `ghost.ok`) → `pbPlace` (6005: `gh.mk()`, `b.mine=true`, `stageProject`, hamlet flag for a far fire, `PLAYER.project=b`, un-pause, avatar starts at once) → `pbStatus` (6030: "Label · k of n [· paused | · needs X (none in the store)]") in `#gstat` → `#bPause` toggles `PB.paused` and pulls the avatar off the site (12190–12195) → `#bStop` → `pbStop` (6019: refunds delivered `b.got`, clears span tiles, resets the home's tried-flags, `removeBuild`).
- A `b.mine` project never enters `village.queue`, so villagers never work it; the avatar's own `siteJob` fetches from the store when `store[m]-reserveOf(m)>=1` else fells/quarries/cuts (4190–4220), and may fell down to 8 trees instead of the village's 26 (4213). A fire placed >18 tiles from every green founds a hamlet for the avatar's household (`hamletSite` 2519, 5978, 6011, resolved in `founding` 2503).

### 3.5 Returning to creator mode
`#bPlay` → `setMode('creator')` (11260–11264): follow and selection dropped, pick/panel/ghost bar cleared, toast; the avatar stays in the world as an ordinary villager with the `g.player` exclusions above (comment 5626–5629). Terrain tools reappear via CSS (169). `#bNew` (289 → 12169) discards the avatar entirely.

## 6. Simulation core (rules with numbers)

### 6.1 Time, seasons, weather
- `DAYLEN=210` sim seconds per day, `SEASON_DAYS=3`, so a year is 12 days (~42 real minutes at 1×) (573). `T.abs` starts 0.34 (mid-morning, 814). `updateTime` (815–828): `light = clamp01(−cos(2πf)·0.86+0.42)` (fully dark below f≈0.17 / above ≈0.83); `cold` ramps 0→1 over the last autumn day, 1 in winter, 1→0 over the first 0.8 spring day, `max(cold, W.snow·0.6)`; `thaw=1` for the first 2 spring days; season-change log lines (818).
- Day shape (4608–4631): day [0.235,0.68), dinner [0.68,0.76), social [0.76,0.86), night; bedtimes child 0.80 (0.87 at midsummer), baby 0.80, elder 0.865, adult 0.885 ± `bedJit` 0.02; `evening()` = f≥0.68 or <0.235 (nobody works); `LATE_SHIFT=0.045` day after supper at a lantern-lit site (2873, `lateSite` 4623).
- Weather (`WK` 829–838: clear/fair/cloudy/rain/mist/snow/breeze/storm with cloud/rain/mist/snow/wind targets and labels; `updateWeather` 846–881): per-season uniform picks spring [clear,fair,fair,rain,mist,breeze,cloudy,storm], summer [clear,clear,fair,breeze,cloudy,rain], autumn [fair,cloudy,rain,mist,breeze,clear,storm], winter [snow,snow,cloudy,mist,clear,fair,breeze]; durations storm `rnd(70,120)+28` s else `rnd(45,140)` s, first change at 40 s; storm front 0→1 over `STORM_LEAD=28` s then 1→2 rolling out (rain starts at front 0.33, full at 0.67); spate eases with half-lives 18 s up / 80 s down; cloud/rain/mist/snow ease with 2.6 s half-life; wind target × two-sine gust; `W.wet` chases rain 4 s up / 150 s down; cloud drift `wind·22` px/s. Weather uses the sim RNG, so it is seed-reproducible.

### 6.2 Terrain generation, water and erosion
- `genIsland(seed)` (885–1037): reseeds both PRNGs (887); one of four silhouettes (crescent/ridge/bowl/twin → names "Crescent Isle", "Long Ridge", "The Green Bowl", "Twin Fells", 890); fBm height field with square edge falloff `−edge^3.2·0.72`, `E=clamp(h·9·0.96)`; `blurE(5)`; two river passes (spring candidates `E>SEA+2.2`, ≥24 tiles apart; greedy descent; valley half-width 8 tiles with monotone floor; channel bed `E−0.65`; spring rates 2.2 then 2.5); soil `clamp(0.95−slope·0.40−max(0,E−6)·0.14, 0.12, 1)`, `KSOFT` 0.55–1.45; river bed bedrock; `setMaterials` (1051: WAT if depth>0.12, SNW ≥8.1 & snowy, ROK/SCR if soil<0.06 or slope≥1.9, SCR ≥8, SND ≤2.95, GRS ≥6, else MEA); 320 flower tries, 600 cover tries (visual RNG); founders' camp scored flat / ~6 tiles from water / ≈4.2 levels (1022–1035).
- `waterStep(dt)` (1151–1298): active-set shallow water on four owned edges per tile; springs fill to cap `0.55·(1+spate·0.6)` with weights `[.40,.15,.15,.15,.15]` and `rainFactor` (spring ×1.35, summer ×0.72, winter ×0.55, thaw ×1.6, ×(1+rain·1.9)(1+spate·2.2)); rain adds +0.030 to up to 180 random land tiles when `W.rain>0.28`; `edgeFlux` pushes by head × `G_ACC=12`, thin-film hold (`WD<=0.004` or `<0.06` with head <0.25), friction `0.6+0.04·film·|f|/d³`; outflow capped at 90 % of depth; sea tiles hold `WD=SEAS−E` and deposit shoals up to `SEA−0.1`; map border is a sink; still water soaks 0.002/s; erosion only after `erodeHold` 8 s, above `SEA+0.5`, not under DAM/BRIDGE/OCC: `ue=(u>3.5 && w≥0.10 && q≥0.6)? u−3.5 : 0`, capacity `0.068·ue²·q`, cut `(cap−SED)·0.016·KSOFT·dt` (rock ×0.22, max 0.25), deposit `(SED−cap)·1.6·dt`; bend outer-bank wear `0.0007·q·u·s·KSOFT·dt`, inner bar deposition. Sub-stepped at ≤0.034 s (12028).
- Thresholds read everywhere: `FLOW_STREAM=0.5`, `FLOW_RIVER=1.3`, `FLOW_ICE=4.0` (1349–1351); drawn-water `wetLo` 0.045 flowing / 0.09 still (692); AI "water" `wetD>0.12` and not ice (`isWater` 684).
- `iceStep` (1116) every 1.6 s: freeze at `cold>0.6` from banks with 40 % chance (not sea, not springs, `FLOW<4`); thaw at `cold<0.45` with an open neighbour 30 %; log lines "The river has frozen over…" / "The ice has gone…".
- `slumpStep` (1311) every 0.25 s: banks steeper than 0.32 (soil) / 1.5 (rock) / 0.75 (fresh creator earthwork within `RELAX_T=60` s) relax toward neighbours; soil regrows +0.0012/s, sand greens −0.00025/s.
- `updateFlora` (5717–5804): trees fall at 0.95/s then stump 26 s; saplings mature in ~2.4 days; seeding cap 1600 trees; rocks trickle to `max(10, 3·gnomes)`; bushes regrow up to 6 berries (rate by season), spread cap 800; hive honey +1 per 3 days in spring/summer; trap stock +1/45 s (half in winter) cap 3; fires/cabins/lodge burn `store.wood` in the cold (fire 0.011/s, ×0.5 with a hearth; cabin/lodge 0.006/s) and go `out` when dry; garden crop +1 per 3.2 days (×0.55 untended, ×1.25 with a hive, ×0.4 in a dry spell unwatered), apple tree matures in 20 days, 3 apples each autumn; wheel/windmill spin, `village.power` when windy at night; frost/thaw flags.

### 6.4 Households, children, population
- `households()` (4327–4386) on the 1.2 s planner tick: a single adult (not elder, not player) pairs with the nearest unrelated (`related` 4230: parents/siblings/first cousins/aunt-uncle) adult single of the other sex → both `court` 16 s at their midpoint; tents merge; cabin starts when `store.food ≥ 6` and a woodpile and drying rack exist, choosing a craft house (`craftHome` 2998: woodcutter/fisher/miner/shepherd/farmer by top craft) else a cabin on the ring; couples take over empty cabins; singles pitch a tent 5–9 tiles from the parents' cabin.

### 6.5 Villages and the construction economy

## 8. Audio

- Zero assets: everything is a scheduled sine `tone(freq, dur, o)` (6090–6113: exponential envelope, attack 0.045 s, glide `to` ending at 92 % of duration, LFO `wob/wobd`, pan via `StereoPannerNode` when available, `dry` skips reverb). Graph (`initAudio` 6056–6072, built on the Begin tap 12217 or a sound-check button 10788): master 0.84 → lowpass 2100 Hz Q 0.3 → highshelf −6 dB above 1100 Hz → compressor (−24 dB, knee 28, 3:1, 30/450 ms) → destination; shared convolution reverb from a 2.2 s synthetic noise IR (`makeIR` 6073, decay 2.8) → lowpass 1600 → return 0.36.
- Spatialisation: `panOf` (6081) = screen x relative to centre over `0.55·cw`, clamped; `audibleGain` (6085) = `1 − max(|dx|/0.85cw, |dy|/0.85chh)` (≈0.41 at the screen edge); `gtone` (6114) bails below 0.02 and scales gain by audibility.
- Cue rate limiting (v9.11, `aOK(kind, baseMs, soft)` 6131–6137): one real-time gap per kind in `AGAP`; gap = base × speed (1–20) for hard cues, base × `1+0.45·(speed−1)` for voice-like soft cues (×9.55 at 20×). Base gaps: chop/knock/tap 90 ms; drop 120; splash 150; eat 220; hup 250; thud 300; yell 420; creak/giggle/fall 450; moan/panic/crash/built 500; help/snicker/comfort 600; murmur 700; yip/baby/leave 900; burner 1800 (11584); rumble 2500; music box 9000. Known flaw: `aOK` is checked before audibility, so an off-screen cue silences an on-screen one of the same kind (reader 12).
- 27 named cues (6139–6207): chop, knock, tap, drop, eat, moan, hup, splash, yell, panic ("oh-oh"), help (three falling notes), creak, giggle, snicker (fox), murmur, comfort, fall (tree), thud (dead in-game), crash (bridge), rumble (thunder, unpositioned), built (chord with a 0.4 floor), yip (dog), baby, tune (12-note pentatonic music box for dances/feasts), leave, owl, dove (the last two have no attenuation or gap). - Birdsong (6212–6269): `noteRun` schedules phrases; six procedural voices `VOICES` (6220: robin, warbler, thrush, chiffchaff, blackbird, wren); `singFrom` (6252) picks a voice from a tree near the view (`aTreeNearView` 6259 samples 24 trees) and perches a decorative bird (`landBird`, visual RNG). ## 11. Persistence

- **None.** `grep -ci 'localStorage|sessionStorage|indexedDB'` on the file returns 0 (verified). No `JSON.stringify`/cookie use is reported by any reader.
- The only state that survives a reload is the seed in the URL hash: `newIsland` writes `#s=<seed>` via `history.replaceState` (12115), `seedFromHash` (12097–12100) reads it, and `/halt/.test(location.hash)` at 814 starts the sim paused for harness runs (`#s=101&halt`). Everything else — eroded terrain, buildings, gnomes, the avatar, `MODE`, tool, brush, speed, `muted` (6055), `lang` (12206), the undo stack (11086), the event log (10708) — is in-memory and reset by `newIsland` (12101–12126) or lost on reload. `#bNew` has no confirmation (12169).
- The substitute for saving is determinism: twin seeded PRNGs (583–598), fixed 1/60 s steps (12054), `rngN` and `simSteps` counters exposed on `window.__GV` (12223–12241) for an external `det.js` harness (comment 12022). A future save would have to assign ids: runtime state is held as object references (`g.mate`, `g.home`, `g.job.b`, `c.master`, `f.home`, `b.owners`, `b.moveFrom`…).
- PWA posture is half-finished: `apple-mobile-web-app-capable` (7) without a manifest, icon or service worker; fonts need the network (10–12).
